[Square](/ja/articles/square)と[Stripe](/ja/articles/stripe)は、どちらも「カード決済を受け付けられるようにするサービス」として並べられることが多い。ただし料金表を横に置くと、行の立て方からして違う。Squareの行は「対面」「オンライン」「請求書」「ブラウザ決済」という決済の場面で、Stripeの行は「カード」「コンビニ」「PayPay」「銀行振込」という決済手段と、「Billing」「Invoicing」「Terminal」という機能の部品だ。この記事は、日本向けの公式ページを2026年10月1日に読み、書かれている数字と条件をそのまま並べる。当サイトは両サービスを契約して使った体験を書いているのではなく、公開されている料金表とドキュメントを突き合わせている。料金は改定されるので、申し込む前に必ず公式ページを確認してほしい。

## 日本の手数料を並べる

:::fact
以下は、Squareの料金ページ・ヘルプセンター・各決済手段のページと、Stripeの日本向け料金ページ・サポート記事（いずれも2026-10-01閲覧）に書かれている内容を、当サイトが場面ごとに並べ直したものだ。どちらも年間の取引額が大きい事業者向けに個別の料金（カスタム料金）があると案内しており、表はそれ以外の標準の料金を示す。

| 場面 | Square（日本） | Stripe（日本） |
| --- | --- | --- |
| 初期費用・月額固定費 | 0円 | 初期費用・月額料金なし |
| 対面のカード決済 | 2.5%〜。年間キャッシュレス決済額3,000万円未満で、Visa・Mastercard・American Express・JCB・Diners Club・Discoverの対面決済の場合。それ以外は3.25%〜またはカスタム手数料 | Terminalで3.24%。Tap to Payはオーソリごとに18円を加算 |
| 対面の電子マネー | 3.25%（交通系IC・iD・QUICPay） | Terminalは iD や QUICPay など国内専用の非接触ネットワークに対応しないと記載 |
| 対面のQRコード決済 | 3.25%（PayPay・d払い・楽天ペイ・au PAY・メルペイ・WeChat Pay・Alipay+） | Terminalの対応決済手段の表に記載なし |
| オンラインのカード決済 | 3.6%（eコマースAPI、リンク決済、オンラインビジネスの無料プラン） | 3.6%。通貨換算が必要な場合は2%を加算 |
| 請求書でのカード決済 | 3.25%。カード情報の手入力・保存済みカードの利用は3.75% | Paymentsの手数料に加えて、Invoicing Starterが支払い済み請求書あたり0.4%（Plusは0.5%） |
| カード情報の手入力（ブラウザ決済） | 3.75% | 該当する料金の行は確認できなかった |
| 定期課金 | Square サブスクリプションは月額固定費0円・3.6%（請求書の支払いは初回3.25%、2回目以降3.6%） | Paymentsの手数料に加えて、BillingがBilling取引額の0.7% |
| コンビニ決済 | オンライン決済の手段一覧に記載なし | 3.6%（最低手数料120円） |
| 銀行振込 | オンライン決済の手段一覧に記載なし | 1.5% |
| オンラインのPayPay | オンライン決済の手段一覧に記載なし | 3.98%（デジタルコンテンツ事業向けは9.48%） |
| チャージバック | 管理サービスに手数料は発生しない | 不審請求の申し立て受領手数料として1件1,500円 |
| 返金 | 払い戻し手数料なし | 標準の料金体系では、銀行振込を除き返金に伴う手数料は発生しない。元の取引の決済処理手数料は返金されない |
:::

:::fact
手数料にかかる消費税の扱いは、両社の公式ページで書き方が異なる。Squareのヘルプセンターは「決済手数料は決済方法にかかわらず、全て不課税」とし、即時入金サービスの1.5%の手数料も不課税で、決済手数料に対する領収書は発行しないと書いている。一方でSquareのQRコード決済のページは、QRコード決済の対面決済手数料を「3.25%（税込）」と表記している。Stripeのサポート記事は、日本のStripeアカウント所有者に対して一部の手数料に現行の標準税率で日本の消費税が適用され、消費税は「Stripe の製品およびサービス手数料に加えて適用されます」と書いている。同記事の表では、JCB・American Express・Discover・Diners Club・コンビニ決済・PayPay・日本の銀行振込・不審請求の申し立て・Billingなどのソフトウェアが課税対象で、VisaとMastercardは2026年4月1日以降、通貨換算（FX）は2025年10月31日以降に対象となっている。ストライプジャパン株式会社は適格請求書発行事業者として登録されており、手数料の適格請求書は毎月10日までにダッシュボードに表示されるという。
:::

:::guess
料金表の率だけを見ると、対面のカード決済はSquareの2.5%〜とStripe Terminalの3.24%で差があり、オンラインのカード決済はどちらも3.6%で並ぶ。ただし公式の説明どおりなら、Squareの手数料は不課税で、Stripeの手数料には消費税が別に加わるため、同じ3.6%でも事業者の手元から出ていく金額は一致しないとみられる。消費税を仕入税額控除できる課税事業者と、控除できない免税事業者とでは、この差の重みも変わると考えられる。税務上の扱いは事業者ごとに異なるので、両社のページが勧めるとおり税理士に確認するのが確実だ。
:::

リーダー以外には12回または24回の分割払いの記載がある。「iPhoneのタッチ決済」のページによれば、iPhone XS以降のiPhoneに無料のSquare POSレジアプリを入れれば、カードリーダーなしでクレジットカードとApple Payのタッチ決済を受け付けられる。ただし電子マネー（交通系IC・iD・QUICPayなど）はiPhoneのタッチ決済では受け付けられず、Squareの決済端末が必要だと書かれている。
:::

:::fact
Stripeの対面決済はStripe Terminalという製品で、ドキュメント（2026-10-01閲覧）では日本は対応国の一覧のうち「(ベータ)で利用可能」の区分に入り、日本向けの節の見出しは「Terminal を日本に導入する (プレビュー)」となっている。日本で使えるリーダーとして挙がっているのは、スマートリーダーのStripe Reader S700、モバイルリーダーのBBPOS WisePad 3、iPhoneのタッチ決済だ。対応ブランドはVisa・Mastercard・American Express・JCB・Discoverで、Dinersは日本ではサポートされないと注記されている。日本向けの料金ページに載るリーダーの価格は、BBPOS WisePad 3が10,480円、Stripe Reader S700とS710が46,480円、リーダーのモバイル通信がリーダーごとに月額1,580円。これらの価格が税込か税別かの表記は、料金ページでは確認できなかった。Terminalの説明には「カスタム POS アプリを開発やサードパーティーの POS システムと連携可能」とあり、SDKとAPIでの連携に加えて、コーディング不要のソリューションも案内されている。
:::

:::pull
Squareの端末は、自社の無料POSレジアプリと組で案内されている。Stripeの端末は、自分たちのPOSや業務システムにつなぐための部品として案内されている。
:::

## 入金のタイミングと条件

:::fact
Squareの料金ページとヘルプセンター（2026-10-01閲覧）によれば、登録口座が三井住友銀行またはみずほ銀行の場合、0:00から23:59の間に発生した売上は翌営業日に振り込まれる。その他の金融機関の場合は、毎週木曜日0:00から翌週水曜日23:59までの売上が、その週の金曜日にまとめて振り込まれる。振込手数料はSquareが負担し、加盟店への請求はない。土日祝日は振込が行われず、翌営業日になる。これとは別に、送金額の1.5%の手数料で使える即時入金サービスがあり、最低振込額は5,000円とされている。
:::

:::fact
Stripeの入金に関するドキュメント（2026-10-01閲覧）は、日本について「日次入金は利用できません。デフォルトのスケジュールは手動であり、週次および月次の入金スケジュールも利用できます」と書いている。国別の売上処理タイミングの表では、日本は初回が7暦日、以降のデフォルトが4営業日。入金先は日本の金融機関の普通預金または当座預金の口座で、大手銀行、ネット銀行、ゆうちょ銀行が例に挙がっている。入金手数料については「Stripe が通常の入金手続きで手数料を請求することはありません」とあり、日本の最低入金額は1円。コンビニ決済のドキュメントは、支払いの確認後、売上は4営業日後に入金可能になると説明している。
:::

:::guess
入金の説明の仕方にも、両社の向いている相手の違いが表れているとみられる。Squareは銀行名と曜日で「いつ口座に入るか」を言い切り、Stripeは「売上がいつ入金可能になるか」と「入金をいつ実行するか」を分けて、スケジュールを事業者に選ばせる。前者は店頭の売上を翌日の仕入れに回したい店主に、後者は入金を会計処理や資金管理の周期に合わせたい事業者に向けた書き方だと推測される。どちらが早く着金するかは、登録する銀行と選ぶスケジュールによって変わる。
:::

## コードを書かずに使える範囲と、決済手段の広さ

:::fact
Squareのヘルプセンターの「対応しているオンライン決済の手段一覧」（2026-10-01閲覧）には、コードを書かずに使える製品として、Square 請求書、Square オンラインビジネス（ネットショップ）、Square リンク決済、Square サブスクリプション、Square 予約、Square ブラウザ決済が並ぶ。支払い手段はクレジットカード、Apple Pay・Google Pay、製品によってSquare Payで、オンラインで対応するカードブランドはVisa・Mastercard・Amex・JCB・Diners Club・Discoverとされている。Square 請求書は無料プランが月額0円で請求書と見積もりを無制限に作成・送信でき、有料の「請求書 プラス」は月額3,000円。オンラインストアは無料プランのほかに「¥3,375〜」と表示された有料プランがあり（ページ上で課金の周期は確認できなかった）、プレミアムプランでは決済手数料が3.3%になる。
:::

:::fact
Stripeの日本向け料金ページ（2026-10-01閲覧）によれば、Payment Linksは「ウェブサイト不要でオンライン販売が可能な、ノーコードの決済用リンク」で、標準の料金体系ではPaymentsの手数料に追加料金なしで含まれる（独自ドメインは月10ドル）。Invoicingは「コーディング不要で、請求書をわずか数分で作成、カスタマイズ、送信できる」とされ、Billingはサブスクリプションや従量課金の請求を扱う。オンラインの決済手段としては、カードとウォレットのほかにコンビニ決済、PayPay、銀行振込が日本の料金表に載っている。コンビニ決済のドキュメントによれば、対象はファミリーマート・ローソン・ミニストップ・セイコーマートで、Billingにも対応する。PayPayのドキュメントによれば、PayPayはPayment Links・Checkout・Elementsで使え、継続課金には対応しない。
:::

:::guess
請求書を送る、決済リンクを貼る、月額課金を受けるという3つの用途は、どちらのサービスでもコードを書かずに始められるとみられる。違いが出るのは、その先だと考えられる。Squareは請求書・ネットショップ・予約・POSレジを同じ管理画面の完成品として持ち、店頭の端末と在庫や顧客の情報がつながる。Stripeは決済手段の幅（コンビニ・銀行振込・PayPay）と、Billing・Invoicing・Taxといった部品をAPIで自社のサービスに組み込める点に厚みがある。Squareにも20種類以上のAPIがあり、Stripeにも対面決済のTerminalがあるので、どちらか一方にしかできないことは多くない。重心がどこにあるかの違いだと当サイトは見ている。
:::

## 審査と始めるまでの説明

:::fact
Squareの料金ページのFAQ（2026-10-01閲覧）によれば、アカウント作成後、Visa・Mastercard・American Express・UnionPay（銀聯）の審査には通常1〜3営業日かかり、最短でアカウント作成の当日から利用できる。JCB・Diners Club・Discoverは株式会社ジェーシービーの審査が完了してから使え、通常5〜15日。QRコード決済は各QRコード決済事業者の審査があり、通常30日以内に完了する。決済代金の振込は登録した銀行口座の確認が完了してから始まり、これは通常1〜3営業日。ヘルプセンターは、Squareの審査に加えて、Visa・Mastercard・UnionPayは三井住友カード株式会社、アメリカン・エキスプレスはAmerican Express International, Inc.、JCB・Diners Club・Discoverは株式会社ジェーシービーによる審査が求められ、結果によっては一部のブランドを利用できない場合があると記している。FAQには、個人事業主も無料のアカウント登録で導入できるとある。
:::

:::fact
Stripeのドキュメント「アカウントを設定する」（2026-10-01閲覧）によれば、アカウントを作成するとサンドボックスでStripeのサービスをテストでき、本番環境で使うにはビジネス情報の確認を行い、有効化の要件を満たす必要がある。KYC（顧客確認）の義務により全ユーザーに対してこの情報を収集・保持するとされ、利用規約を遵守しているかを確認するための審査を行い、追加で必要な情報がある場合は連絡すると書かれている。利用するサービスが増えると、追加の情報や確認を求める場合があるという。当サイトが確認した範囲のStripeのページには、審査にかかる日数の目安は書かれていなかった。
:::

## どんな事業にどちらが合いやすいか

ここからは、上の料金表と条件を当サイトが読んだうえでの整理だ。優劣を付けるものではなく、事業の形ごとに、公式の料金表のどの行が効いてくるかを示す。

:::guess
- 店舗でカード・電子マネー・QRコードをまとめて受けたい場合は、Squareの料金表が当てはまりやすいとみられる。対面カードの2.5%〜（条件付き）と、電子マネー・QRコードの3.25%が1つのアカウントに載っており、端末は税込4,980円のリーダーから選べる。StripeのTerminalは日本ではプレビューの扱いで、iDやQUICPayには対応しないと明記されている。
- イベントや出張での販売は、端末を持ち歩くか、iPhoneのタッチ決済を使う形になる。SquareもStripeもiPhoneのタッチ決済を日本向けに案内しているが、Squareは無料のPOSレジアプリでそのまま使え、Stripeは自社のアプリや他社のPOSとの連携を前提にした説明になっている。アプリを自分で用意しない事業者にはSquareのほうが手数が少ないと推測される。
- 取引先に請求書を送ってカードで払ってもらう場合、料金表の上ではSquare 請求書が3.25%で月額0円、StripeはPaymentsの3.6%にInvoicingの0.4%が加わる。一方、取引先が銀行振込で払いたい場合は、Stripeの料金表に銀行振込1.5%の行があり、Squareのオンライン決済の手段一覧には銀行振込の行がない。相手がどの手段で払うかで選び方が変わると考えられる。
- 自社のWebサービスやアプリに月額課金を組み込むSaaSやオンライン講座は、Stripeの設計が合いやすいとみられる。Billingは0.7%が上乗せされるが、トライアルや割引、従量課金、支払いの再試行（Smart Retries）といった機能をAPIで自社のプロダクトに組み込める。月謝や会費を定額で集める教室やジムのような用途なら、Squareのサブスクリプションや定期請求書でも足りる可能性がある。
- ネットショップでコンビニ決済やPayPayを選べるようにしたい場合は、Stripeの料金表にその行がある。店頭の在庫とネットショップの在庫を1つにしたい場合は、Square オンラインビジネスがPOSレジと同じアカウントで動く。
- 店頭はSquare、自社サイトの月額課金はStripeというように、両方を使い分ける事業者も少なくないとみられる。どちらも月額固定費がかからない料金体系なので、併用しても固定費は増えない。そのかわり売上の入金と帳簿が2系統に分かれる点は、あらかじめ織り込んでおく必要がある。
:::

## なぜ料金表の形が違うのか

:::fact
[Squareの解剖記事](/ja/articles/square)によれば、Squareは2013年5月に三井住友カードをアクワイアラーとして日本でサービスを始め、親会社Block, Inc.のForm 10-Kはハードウェアを自社設計と記し、日本ではJCBと電子マネーに対応すると明記している。同社は加盟店に対して「merchant of record」と決済サービス事業者の両方を務める。[Stripeの解剖記事](/ja/articles/stripe)によれば、Stripeは「エンドユーザーがStripeの画面を見ることはほとんどない」決済インフラで、収益は決済手数料を中核に、Billing・Taxなどのソフトウェア群へ広がっている。
:::

:::guess
料金表の形の違いは、両社が最初に誰の机の上に製品を置いたかの違いから来ているとみられる。Squareの最初の顧客は、レジの前に立つ店主だった。だから製品は端末とPOSレジアプリという完成品になり、料金表は「店頭で」「請求書で」「ネットショップで」という店主の言葉で区切られる。電子マネーやQRコードのように、日本の店頭で求められる決済手段を1つのアカウントに集めているのも、同じ出発点から説明できる。

Stripeの最初の顧客は、決済を自社のサービスに組み込む開発者だった。だから製品はAPIという部品になり、料金表は決済手段と機能の単位で区切られ、使った部品の分だけ率が積み上がる。コンビニ決済や銀行振込のように、オンラインの購入者が選ぶ手段が厚いのも、その延長にあると考えられる。対面決済のTerminalが「POSを作る、またはPOSにつなぐ」ための製品として説明されているのは、Stripeにとって店頭もまた、開発者が組み立てる1つのチャネルだからだと推測される。

2社は互いの領域に踏み込んでいる。SquareはAPIとネットショップを持ち、Stripeは端末とノーコードの決済リンクを持つ。それでも料金表の区切り方が変わらないのは、製品の形が出発点の顧客に合わせて作られ、後から足した機能もその枠の中に置かれているためとみられる。
:::

SquareとStripeは、同じカード決済を別々の入口から売っている。Squareは店頭の端末から入り、請求書やネットショップへ広げた。StripeはAPIから入り、ノーコードの画面や端末へ広げた。申し込む側が見るべきなのは、どちらの率が低いかより、自分の売上がどの場面で、どの決済手段で立つかだ。対面が中心で電子マネーやQRコードも受けたいのか、オンラインが中心でコンビニ決済や月額課金が要るのか。その答えが決まれば、2つの料金表のどの行を読めばよいかはおのずと決まる。
